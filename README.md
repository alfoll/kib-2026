# Статья КИБ-2026: LaTeX-проект

Готовый каркас для написания и сборки PDF по требованиям КИБ-2026.
Это **неофициальный** LaTeX-шаблон, подготовленный по сайту и двум документам
организаторов, сверенным 20.10.2026. Научная тема и содержание в нём не утверждены.

**Важно:** КИБ требует **две полные страницы А5 в DOCX и PDF**. Этот проект
автоматизирует PDF. Порядок подготовки обязательного DOCX описан ниже.
Шаблон не гарантирует две страницы при произвольной длине текста: объём регулируют
редактурой содержания, не уменьшением шрифта или полей.

## Быстрый старт

После создания репозитория в аккаунте `alfoll`:

```bash
git clone https://github.com/alfoll/kib-2026-paper.git
cd kib-2026-paper
python scripts/build.py
```

На Windows вместо `python` можно использовать `py`, на macOS/Linux — `python3`.
Если репозиторий ещё не создан, распакуйте архив проекта и откройте терминал в
распакованной папке. Команда сборки работает одинаково.

Результат: **`build/main.pdf`**. Первоначально в PDF находится демонстрационный
текст об использовании шаблона; это не статья и не готовый материал для подачи.
Перед отправкой замените все заполнители. Строгая проверка намеренно отклоняет их.

## Что установить

Нужны Git, Python 3.10+ и дистрибутив LaTeX с **XeLaTeX**. Обычный `pdflatex`
не подходит: проект использует системный Times New Roman и Unicode.

### Windows

1. Установите Git: https://git-scm.com/downloads
2. Установите Python: https://www.python.org/downloads/ (добавьте Python в PATH).
3. Установите MiKTeX: https://miktex.org/download
   или полный TeX Live: https://tug.org/texlive/.
4. Для MiKTeX разрешите установку недостающих пакетов и обновите его через MiKTeX Console.
   В настройках языков включите Russian и обновите форматы, если журнал сообщает
   об отсутствии русских шаблонов переносов.
5. Проверьте наличие четырёх начертаний Times New Roman в системе.
6. Перезапустите терминал, выполните `xelatex --version` и `py --version`.

Инструкция MiKTeX: https://miktex.org/howto/install-miktex.
Основной Python-сборщик не требует Perl или latexmk.

### macOS

1. Установите MacTeX: https://tug.org/mactex/ (полная установка проще для начинающего).
2. Установите Python 3 и Git, если их нет.
3. Установите Times New Roman из законно доступной копии, например вашей установки Office.
4. Если `xelatex` не найден, добавьте `/Library/TeX/texbin` в PATH и откройте новый терминал.

```bash
xelatex --version
python3 scripts/build.py
```

### Ubuntu / Debian

```bash
sudo apt update
sudo apt install git python3 python3-venv texlive-xetex texlive-lang-cyrillic texlive-latex-extra texlive-fonts-recommended
```

Times New Roman устанавливается отдельно. Там, где пакет доступен, можно
использовать `ttf-mscorefonts-installer` после ознакомления с лицензией Microsoft.
Состав репозиториев ОС отличается; проект не требует загрузки шрифтов из
неизвестных архивов. Альтернатива — локальные лицензированные файлы в `fonts/`.

### Шрифт обязателен

Основная сборка останавливается, если Times New Roman не найден, и не подменяет
его похожей гарнитурой. Подробности: [fonts/README.md](fonts/README.md).
Для предварительной проверки без TNR доступно:

```bash
python scripts/build.py --preview
```

Для этого нужен DejaVu Serif (Linux: `fonts-dejavu-core`). Файл `build/preview.pdf`
**нельзя отправлять** в КИБ. После перехода на TNR изменятся переносы и объём.

Результаты проверки основной сборки: [docs/VALIDATION.md](docs/VALIDATION.md).

## Где писать

| Файл | Что менять |
|---|---|
| `content/metadata.tex` | УДК, авторы, организации, город, название |
| `content/abstract.tex` | Аннотация одним абзацем, 5–8 строк в готовом PDF |
| `content/body.tex` | Основной текст, формулы, таблицы, рисунки |
| `content/references.tex` | Реальные использованные источники, по порядку первого цитирования |
| `main.tex` | Порядок подключения частей; обычно менять не нужно |
| `kib2026.cls` | Все настройки оформления; не менять ради подгонки объёма |
| `REQUIREMENTS.md` | Полный перечень официальных требований и их источников |
| `AGENTS.md` | Инструкции Codex по работе в этом проекте |
| `examples/snippets.tex` | Комментированные примеры рисунков, таблиц и формул |

Вводите обычный русский текст в UTF-8. Пустая строка создаёт новый абзац.
Не ставьте `\\` в конце каждой строки: переносы выполняются автоматически.
Служебные символы экранируйте: `\%`, `\_`, `\&`, `\#`.

Заголовки: `\section{Постановка задачи}` — без номера, 10 пт, полужирные по центру.
Они необязательны. Заголовок доклада автоматически переводится в верхний регистр;
фамилии в `ArticleAuthors` нужно писать прописными самостоятельно.

Для нескольких организаций используйте индексы `\textsuperscript{1}`, `\textsuperscript{2}`
после авторов и перед соответствующими организациями; строки организаций можно
разделять `\\`. Пустые строки вокруг названия и аннотации формирует класс.

### Ссылки и библиография

```latex
Текст со ссылкой на источник \cite{key}.
```

```latex
\begin{thebibliography}{9}
\bibitem{key} Фамилия И.О. Название работы. Название журнала.
2026, т. 1, № 1, с. 10–15.
\end{thebibliography}
```

Это схема записи, а не существующий источник. Подставляйте проверенные сведения.
Размещайте `\bibitem` в порядке первого цитирования. В тексте получится `[1]`,
в списке — `1.`. Для длинных ссылок используйте `\url{https://...}`.

### Рисунки, таблицы и формулы

См. `examples/snippets.tex`. Изображения храните в папке `figures/` и включайте
через `\includegraphics`. Они должны быть чёрно-белыми и читаемыми в А5.
У таблиц `\caption` стоит перед таблицей, у рисунков — после изображения.
Для узкой таблицы её название и содержимое помещайте в одинаковую `minipage`.

Ссылки: `\figref{fig:key}`, `\tabref{tab:key}`, `формула~\eqref{eq:key}`.
Нумерация рисунков/таблиц автоматически скрывается, если объект этого вида один.
Три прохода XeLaTeX обновляют счётчики и ссылки. Одну формулу без ссылки набирайте
в `equation*`; несколько формул или одну со ссылкой — в `equation`.

## Сборка и проверка

```bash
python scripts/build.py
```

Команда запускает XeLaTeX трижды без shell-escape, сохраняет PDF и журнал в
`build/`, сообщает об ошибках. Для автоматической проверки финального материала:

```bash
python -m venv .venv
# Windows:
.venv\Scripts\activate
# macOS/Linux:
source .venv/bin/activate
python -m pip install -r requirements-dev.txt
python scripts/build.py --check
```

Выполняйте только строку активации для своей ОС. На macOS/Linux начальную команду
может потребоваться написать как `python3 -m venv .venv`.

Проверяются число/размер страниц, строки аннотации, встраивание шрифтов,
Times New Roman для русского текста, выход текста за поля, ошибки ссылок,
порядок библиографии, отсутствие основных заполнителей. Проверка **не** оценивает
научную достоверность, полноту второй страницы или все свойства изображений.
Формулы допускают специализированные математические шрифты.

При 1 или 3 страницах отредактируйте содержание. Не меняйте поля/кегли и не
добавляйте пустую страницу. При длинном названии и иной аннотации пагинация меняется.
После каждого существенного изменения просматривайте обе страницы.

Альтернативная сборка при установленном latexmk:

```bash
latexmk main.tex
```

Для VS Code установите расширение LaTeX Workshop и latexmk (MiKTeX может
потребовать Perl для latexmk). Настройки проекта уже содержат рецепт XeLaTeX.
Для основной сборки без VS Code достаточно Python-команды выше.

## Обязательный DOCX

В `docs/official-template.docx` сохранён исходный шаблон организаторов.
После завершения текста перенесите материал в его копию, соблюдая
`REQUIREMENTS.md`. Формулы должны оставаться редактируемыми формулами Word,
таблицы — таблицами. Вставка страниц PDF как картинок не подходит.

Pandoc может помочь перенести текст, но не гарантирует сохранение специальных
команд класса, переносов, подписей и двухстраничной вёрстки. В этом проекте
автоматический экспорт DOCX намеренно не объявлен готовым к подаче.
Проверьте идентичность содержания DOCX и PDF, оформление и две полные страницы
в обеих версиях. Если после финальной вёрстки Word переносы существенно отличаются,
согласуйте окончательную пару файлов; не сдавайте две разные редакции.

## Перед отправкой

- Заменены все шаблонные сведения и демонстрационный текст.
- Есть постановка задачи, решение, новые идеи или эксперименты, заключение и выводы.
- Аннотация 5–8 строк, содержит цель и результат.
- Ровно две полные страницы, Times New Roman, поля и размеры не изменены.
- Рисунки чёрно-белые; подписи, ссылки и номера проверены.
- Источники реальны, процитированы по порядку; список соответствует тексту.
- Готовы согласованные DOCX и PDF, экспертное заключение и согласие.
- Актуальные сроки и способ подачи сверены на https://kib.mephi.ru/.

## Git и публикация репозитория

Рекомендуется приватный репозиторий для незавершённой статьи. Сборочные файлы,
шрифты и виртуальное окружение исключены из Git. Для нового локального проекта:

```bash
git init -b main
git add .
git commit -m "Add KIB 2026 LaTeX template and formatting rules"
```

Затем создайте пустой приватный репозиторий `kib-2026-paper` в своём GitHub
и выполните команды подключения remote, которые покажет GitHub. Если установлен
и авторизован GitHub CLI, возможна команда:

```bash
gh repo create alfoll/kib-2026-paper --private --source=. --remote=origin --push
```

Не выполняйте создание повторно, если репозиторий уже существует. Файлы официальных
документов сохранены как источники требований; проект не выдаёт их за свою разработку.
